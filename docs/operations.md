# 循动 4.3 运维与上线检查

本文说明如何检查和配置，不表示线上服务已经升级或已完成备份。任何数据库连接串、密码、推送私钥都不应发到聊天、截图或提交到 GitHub。

## 1. 找到 Render 的 Environment

1. 打开 [Render 控制台](https://dashboard.render.com/)，登录部署网站使用的账号。
2. 进入包含该项目的工作区。如果看到项目卡片，先打开项目，再进入显示 `sports-platform-6809.onrender.com` 地址的 **Web Service**。
3. 点击服务名称，进入有 Events / Logs / Settings 等入口的服务详情页；**Environment** 在这个服务的左侧导航里。窄屏下先展开导航菜单，或用电脑查看。
4. 点击 **Environment**，在 **Environment Variables** 区域找 `DATABASE_URL`，也检查该页关联的环境变量组。只确认键名和数据库类型，不必把完整值展示给别人。

如果当前页面是 GitHub 登录、自己的网站或工作区总览，还没有进入服务设置。不要误点工作区的 Environment Groups 来替代服务的 Environment。导航路径依据 [Render 环境变量文档](https://render.com/docs/configure-environment-variables)。

| 结果 | 下一步 |
| --- | --- |
| 有 `DATABASE_URL`，类型为 `postgres://` 或 `postgresql://` | 确认连接的是长期保留的数据库、可用备份和恢复方式，再更新服务。 |
| 有 `DATABASE_URL`，以 `sqlite:` 开头 | 确认文件路径是否位于实际挂载的持久磁盘，并备份该文件。 |
| 服务/关联变量组都没有 `DATABASE_URL` | 本项目通常会使用相对路径 `sports.db`；同时检查启动命令是否自行设置变量，不能直接认定已经持久化。 |

## 2. 保护已有数据，再升级

Render 免费 Web Service 闲置十五分钟会休眠，部署、重启或休眠会丢失临时文件系统的改动；免费服务不能挂载持久磁盘。免费 Render Postgres 创建三十天后到期，不适合作为长期保留数据的方案。[Render 免费服务限制](https://render.com/docs/free)

如果现有数据可能只在临时 SQLite 中，先确认备份方案，再操作重新部署、切数据库或重启；这些操作可能使当前文件不可恢复。Render 免费服务不提供 Dashboard Shell/SSH，不能假定可以直接登录复制数据库；需根据现有部署条件确定导出方式。用户界面的“导出记录”只包含训练记录，不能恢复全部账号、聊天、评分和约定。

升级流程：

1. 记录当前代码版本和数据库类型；备份并验证备份可读取。不要把数据库备份放到公共仓库。
2. 尽量在与线上相同数据库类型的独立环境试升级；检查原账号、训练记录和聊天均保留。
3. 在维护窗口停止写入，制作最终备份；同一数据库上运行新版本，启动时增量建表和迁移旧搭子状态。
4. 验证老账号登录、历史记录、双人约定、群聊、权限与通知；再恢复正常使用。
5. 如果升级异常，停止写入，按事先演练的数据库恢复方案处理。仅回滚代码不能保证回滚数据库变更。

### SQLite 备份

对**可访问的本地/持久磁盘 SQLite 文件**，使用 Python `sqlite3.Connection.backup()` 或 SQLite 在线备份接口获得一致副本；也可停止应用并关闭所有连接后复制数据库与必要日志文件。运行中的数据库不要只随意复制一个主文件而遗漏 WAL 数据。备份需在另一目录打开并执行 `PRAGMA integrity_check`，保留至少一个独立副本。

### SQLite 切换 PostgreSQL

设置新的 `DATABASE_URL` 不会搬运旧数据；直接切换会让应用显示一个新库，原账号看起来像“消失了”。迁移必须：

1. 暂停写入并备份源 SQLite；准备空的目标 PostgreSQL。
2. 使用经过验证的数据迁移方案复制全部业务表，保留用户 ID、外键关系、时间字段和密码哈希；不要只导入训练记录。
3. 重置 PostgreSQL 自增序列到已有最大 ID 之后，核对每张表行数和关键关联。
4. 在目标库测试原账号登录、会话、聊天、推送密钥、约定与管理员权限，再切换生产连接。
5. 保留源库备份和回退窗口。推送订阅是敏感会话数据，迁移时应与登录会话一并检查。

本仓库目前没有通用的一键跨库搬迁工具，不应将启动时增量建表误认为跨库迁移。长期使用还需要定期备份和实际恢复演练。

## 3. 服务配置

4.1 新增个人资料、头像和活动封面三张表，启动时增量建表，不改写旧账号与记录。部署时安装更新后的 `requirements.txt`（包含 Pillow 图像处理库）。头像和封面以压缩图片存入数据库，必须随完整数据库备份一起保留；仅导出训练记录不包含图片。更换 `DATABASE_URL` 不会自动迁移这些数据。

4.3 调整首页、活动详情、发布和个人主页，新增完成约定后“再约一场”，不增加数据库迁移。再约生成新的待确认邀请，多人再约不进入公开活动列表，原约定保留。`experience.js`、`profile.js`、对应样式和 `publishing.css` 必须随页面一起部署。可在“我的 → 设置 → 关于循动”核对 4.3.0。

保留 4.2.1 的头像下载失败恢复：`avatars.js` 必须随公共静态资源版本一起部署，头像照片不会写入 Service Worker 或本地持久缓存。升级后检查上传头像、重新打开页面、消息页与活动详情的头像，以及退出登录后的账号隔离。

每个用户最多保留一张当前头像，每条活动最多保留一张当前封面，替换会覆盖原图。上传上限 5 MB，解码上限 2000 万像素；只接受静态 JPEG、PNG、WebP，转成 JPEG 后保存。接口需要登录并检查双方拉黑、账号限制和活动可见性，图片响应使用 `private, no-store`。小范围试用可使用此方案，扩大规模前需监控数据库容量和图片请求负载。

在完成备份和数据库确认后，检查以下环境变量：

| 变量 | 作用 |
| --- | --- |
| `DATABASE_URL` | 生产数据库连接，由部署平台安全保存。未设置时为 `sqlite:///./sports.db`。 |
| `COOKIE_SECURE=true` | HTTPS 线上登录 Cookie；本地 HTTP 使用 false。 |
| `REMINDERS_ENABLED` | 默认开启；设置为 `false` 可禁用进程内提醒任务，测试环境使用 false。 |
| `VAPID_SUBJECT` | 推送联系地址，可用运维邮箱 `mailto:...` 或本站 HTTPS URL；默认是当前循动站点地址。 |
| `AI_API_BASE` / `AI_API_KEY` / `AI_MODEL` | 可选建议服务；不配置密钥时使用内置规则。 |

Python Web Service 构建命令为 `pip install -r requirements.txt`；启动命令可用 `uvicorn app.main:app --host 0.0.0.0 --port $PORT`（Render 的 Linux 命令格式）。多实例共享同一个 PostgreSQL 数据库；初次升级建议单实例完成迁移后再扩展。

VAPID 公私钥由应用生成并存入数据库，不需要在前端填写私钥。数据库备份必须包含推送密钥表，不能随意清空或每次部署重新生成。

数据库类型仍不明时，代码可以先保存到独立功能分支供检查，等完成数据保护再部署。不要为了查看效果而反复点击 Manual Deploy。

## 4. 管理员 test02

用户指定的管理员为精确用户名 `test02`。首次 4.0 迁移只对当时已存在的该账号授予权限，并写入迁移标记；如果当时不存在，后续注册也不会自动获得管理员权限。

在应用完成 4.0 初始化后，由拥有服务器数据库访问权的维护者运行：

```text
python scripts/admin_role.py status --username test02
python scripts/admin_role.py grant --username test02
```

撤销权限：

```text
python scripts/admin_role.py revoke --username test02
```

命令必须在已安全设置目标 `DATABASE_URL` 的终端执行，不会猜测目标数据库，也不会创建用户或运行应用迁移。它会检查精确用户名，`TEST02` 和 `test02` 不混用；重复授权/撤销可安全重复执行。连接失败时不会输出完整连接串。账号不存在时先让账号本人正常注册，再明确授权。

本地开发库示例（仅本机测试库）：

```powershell
$env:DATABASE_URL = 'sqlite:///D:/sports_platform/sports.db'
.\.venv\Scripts\python.exe scripts/admin_role.py status --username test02
```

不要把生产连接串作为命令行参数或写入文档。线上授权要在明确连接生产库的维护环境操作；本地授权不会自动同步到 Render。授权后刷新“我的”，可见举报管理；普通用户直接请求管理接口仍会被拒绝。

## 5. 通知与手机验收

站内提示在网页打开且可联网时工作。系统 Web Push 还依赖浏览器推送服务、通知权限和有效登录；登录会话默认七天，退出登录会撤销该会话的订阅。会话过期需要重新登录。

Android 使用支持标准 Web Push 的浏览器，在消息页主动开启通知；如果拒绝过权限，需在浏览器网站设置中调整。iPhone / iPad 使用支持 Web Push 的版本（iOS / iPadOS 16.4 起），先添加到主屏幕，从图标打开后点击开启通知并授权。推送可能受系统专注模式、通知设置和网络影响。[WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

提醒任务运行在 Web 服务进程内。服务休眠/停止期间不能生成或发送提醒；恢复后仅在十分钟宽限窗口内补发，避免很久以后出现陈旧提醒。长期使用需要持续运行的后端；更大规模需再引入独立调度与告警。持久数据库能保留数据，但本身不能让休眠的 Web 服务执行任务。

每次上线至少完成：

- 两台真机、两个账号互发消息；分别检查前台站内提示、后台系统通知、点击后的正确会话、已读状态。
- 测试拒绝/关闭通知、退出登录、切换账号后不会展示上一账号内容；网络恢复后不会反复提示历史消息。
- 双方确认一次约定，验证两小时/三十分钟前的提醒；再验证取消、改期、退出群组后的提醒变化。
- 在 360/390/430px 宽度与真实软键盘下检查输入框、消息滚动、筛选、横向溢出、主题和减少动态效果。
- 普通用户看不到管理入口且接口无权限；管理员能处理举报，双方看到合适的处理结果。
- 验证重启后账号、记录、聊天和推送密钥仍在；检查数据库备份可恢复。

本地自动化测试不能替代浏览器厂商推送通道和真机系统权限的端到端验收。
